# Ufa Subscription Service

## Части, которые можно было бы улучшить при дальнейшем развитии сервиса

### Порядок событий Redis

При нескольких consumer поздно доставленное событие активации может восстановить уже деактивированную подписку, поэтому при дальнейшем развитии стоит хранить последнюю версию состояния или tombstone.

### Восстановление кэша

После полной потери данных Redis кэш сейчас нельзя автоматически восстановить, поэтому при дальнейшем развитии стоит добавить rebuild из PostgreSQL или управляемый replay событий.

### Проверка пользователя

Сейчас `userId` приходит в запросе. Для учебного задания этого достаточно,
потому что в нём нет пользователей и авторизации.

В рабочем сервисе идентификатор пользователя лучше брать из JWT или сессии.
Тогда пользователь не сможет передать чужой `userId` в запросе.

### Тарифы и цены

Сейчас тариф и его цена находятся в одном enum. Для двух фиксированных тарифов это проще и понятнее.

Если появятся акции, валюты или история изменения цен, тарифы можно вынести
в таблицу. Цена в уже созданном счёте всё равно должна оставаться неизменной.

### Идентификаторы подписок

Сейчас подписки используют числовой идентификатор PostgreSQL. Для одного
приложения и одной базы данных это простой вариант.

UUID можно выбрать, если идентификаторы будут активно использоваться во внешнем
API или создаваться в нескольких сервисах. UUID не заменяет проверку прав доступа.
